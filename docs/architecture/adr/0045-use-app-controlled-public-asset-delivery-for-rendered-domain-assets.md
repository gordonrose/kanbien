# ADR-0045: Use App-Controlled Public Asset Delivery For Rendered Domain Assets

- Status: Accepted
- Date: 2026-05-16
- Deciders: Gordon; Codex
- Supersedes: N/A
- Superseded by: N/A

## Context

ADR-0035 established an object-storage-backed asset foundation. Organization
public logos added a narrower public-rendering concern: some domain-owned
assets need to be visible to unauthenticated public readers while still being
controlled by the app's domain authorization, processing, replacement, cache,
and cleanup rules.

Public user-managed assets are a higher-risk boundary than private attachment
storage because stale, unsafe, or incorrectly authorized bytes can become
externally visible. The platform also needs frontend performance and stable
rendering URLs without exposing storage-provider authority.

Organization public logos are the first approved consumer of this pattern.

## Decision

Public rendered domain assets must be delivered through stable app-controlled
URLs, not through permanent raw bucket/provider URLs.

For Organization v1 primary logos, the stable public URL is:

- `/v1/public/organizations/:organizationId/logos/primary`

The stable URL is domain-owned. The consuming feature decides which asset
relationship is current and public-readable. The `assets` feature and storage
adapter supply verified bytes through public seams without becoming the source
of Organization relationship authority.

Public rendered asset delivery must use:

- processed/accepted output bytes only
- actual-byte verification before public readiness
- malware scanning or an approved equivalent gate before public readiness
- metadata stripping for public derivatives where relevant
- deterministic validators such as `ETag` and `Last-Modified`
- explicit `Cache-Control` posture
- `X-Content-Type-Options: nosniff`
- raw storage URL denial in public responses, admin responses, exports, logs,
  audit details, and errors
- feature-owned replacement behavior that keeps the old public asset or
  placeholder visible until the replacement is usable
- cleanup retry and failure recording for replaced or deleted public bytes

The first approved cache posture for Organization public logos is:

- `Cache-Control: public, max-age=300, stale-while-revalidate=86400`
- deterministic `ETag`
- `Last-Modified`
- cache invalidation signal on accepted replacement or removal
- fallback to five-minute revalidation if invalidation fails

Placeholders are generated by app code from durable domain facts. They are not
fake uploaded assets and are not persisted as asset records just to satisfy a
missing-logo display state.

Same-origin streaming/proxy is the first delivery mode. A CDN may be added
later behind the same app-controlled URL if operations approve the provider,
purge, telemetry, and incident posture.

## Consequences

### Positive

- Public URLs remain stable while storage providers and CDN posture can change
  behind the app boundary.
- Domain features keep relationship authority instead of treating asset
  ownership as publication authority.
- Public rendered assets get consistent cache, replacement, placeholder, and
  raw URL denial rules.
- Frontend consumers can render durable URLs without learning storage keys.
- Future public rendered assets have a clear decision gate before exposure.

### Negative

- App-controlled streaming adds runtime load until CDN support is implemented.
- Replacement visibility depends on cache invalidation plus fallback
  revalidation, so stale bytes may remain briefly if purge fails.
- Public asset consumers need stronger implementation proof than private
  attachment consumers.

### Neutral / Follow-up

- Add a CDN/provider ADR before relying on CDN purge behavior for production
  public assets.
- Additional Organization logo types require their own dimension and rendering
  expansion before adoption.
- Public documents, audio, video, customer-shareable files, and generic file
  hosting remain out of scope unless separately approved.
- If several public asset consumers duplicate telemetry and abuse thresholds,
  add a shared public asset observability policy.
