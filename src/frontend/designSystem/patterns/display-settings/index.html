Contract Highlights

What This Pattern Governs

Every shown control must do real work, groups must stay understandable, and the first app subset stays narrower than the full design-system review payload.

Grouping

Clear control families

Theme, magnification, accent, and direction are grouped intentionally so the payload reads like governed settings instead of one undifferentiated list.

Truthfulness

No decorative controls

Every chip must change real runtime behavior. Preview-only controls are allowed, but they must remain honestly documented as preview-only.

Adoption boundary

Narrower first app subset

The first real app consumer is intentionally narrower, with `theme` and `magnification` approved first while `accent` and `direction` stay design-system-only.
