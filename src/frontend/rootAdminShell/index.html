Adoption Notes

What This Proves

  • `/root-admin` can adopt the governed top-nav without replacing the browser-auth seam.
  • The authenticated shell can preserve measured overflow, mobile nav, and profile-menu behavior.
  • Feature destinations can stay capability-driven even while deeper page UIs are rebuilt later.
Reserved Destination

Root Users

The old in-browser CRUD workspace has been intentionally removed for this POC. The underlying root-user APIs remain the system of record while we rebuild the route against the signed-off design system.

Capability Ownership

  • `root-user.read.visible` keeps this destination permission-aware.
  • `root-user.create`, `root-user.update`, and lifecycle mutations are preserved as backend seams.
  • The next feature-loop slice can rebuild list, detail, and editor states on top of this shell.

Current POC Boundary

This page currently proves navigation, orientation, and route ownership only. It does not yet attempt to recreate the old drawer and table UI inside the new shell.

Reserved Destination

System Root Roles

The previous role table and editor flow are deferred while the top-nav adoption is proven. The route stays visible as the future consumer for the root-role workflow family.

Capability Ownership

  • `root-role.list` and `root-role.read` govern shell access and wayfinding.
  • `root-role.update` and capability-assignment mutations remain live backend seams.
  • The next rebuild slice can add list, editor, and assignment views without changing the shell chrome.

Migration Intent

This POC keeps the destination and language of the old console, but avoids porting the entire legacy UI into the new shell before the design-system loop is proven.
